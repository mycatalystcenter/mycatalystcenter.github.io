INTRODUCTION

Four parts, one automation path.

Each layer has a clear job. Ansible runs the playbook, the collection packages Cisco automation content, the SDK handles API communication, and Catalyst Center applies the requested change to the network.

01
A

Ansible

The automation engine. It reads an inventory and runs human-readable YAML playbooks.

Read the Ansible introduction ↗ 02
C

Catalyst Center

The controller. It exposes intent APIs for design, onboarding, provisioning, assurance, and operations.

Explore the platform APIs ↗ 03
PY

Catalyst Center SDK

The Python client. It maps controller APIs to Python methods and handles authentication and responses.

Open the SDK repository ↗ 04
YML

Ansible collection

The content layer. It provides API modules, workflow managers, roles, examples, and validated playbooks.

Browse the collection source ↗
i
Why workflow managers?

A direct API module usually represents one controller operation. A workflow manager coordinates the validation, dependencies, API calls, asynchronous tasks, and verification needed for a complete outcome.

INSTALLATION

Prepare a clean automation environment.

The collection currently requires Python 3.10–3.14, ansible-core 2.16 or later, and a compatible catalystcentersdk release.

  1. 1

    Create an isolated Python environment

    Keep the automation dependencies separate from your system Python packages.

    TERMINALCREATE ENVIRONMENT
    python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
  2. 2

    Install Ansible, the SDK, and the collection

    Check the compatibility matrix before pinning versions for production use.

    TERMINALINSTALL DEPENDENCIES
    python3 -m pip install "ansible-core>=2.16" catalystcentersdk
ansible-galaxy collection install cisco.catalystcenter
  3. 3

    Provide controller settings securely

    Environment variables keep credentials out of the playbook. Use Ansible Vault or your CI secret store for shared automation.

    TERMINALSESSION VARIABLES
    export CATALYSTCENTER_HOST="https://catalyst-center.example.com"
export CATALYSTCENTER_USERNAME="your-username"
export CATALYSTCENTER_PASSWORD="your-password"
export CATALYSTCENTER_VERSION="3.2.3.0"
export CATALYSTCENTER_VERIFY="true"

    ✓ Keep TLS verification enabled and never commit real credentials.

FIRST WORKFLOW

Create an area with one task.

This example uses site_workflow_manager to ensure an area exists under the global site hierarchy. Re-running it should preserve the same desired state.

01
Create the inventory

Use the collection’s expected host group.

[catalystcenter_servers] catalystcenter_server
02
Declare the outcome

state: merged creates or updates the area.

03
Verify the result

config_verify: true checks the resulting controller state.

SITE.YMLYAML
---
- name: Build the Catalyst Center site hierarchy
  hosts: catalystcenter_servers
  gather_facts: false

  tasks:
    - name: Ensure the Bangalore area exists
      cisco.catalystcenter.site_workflow_manager:
        state: merged
        config_verify: true
        config:
          - type: area
            site:
              area:
                name: Bangalore
                parent_name: Global
$ ansible-playbook -i hosts site.yml Module reference ↗
